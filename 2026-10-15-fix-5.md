## The stacks number, and how it was computed

**0.** The number is computed from the data on every build, and checked a second way:

- **The rule:** a named stack counts only if every pair of its members is a tested pair in `stacks/data.json` (a published study gave both to people), and one study is listed under all of its pairs. That one study is what gives the whole stack to people.
- **The result:** the seven stacks have 18 member pairs between them (Wolverine, GH and Tesa/Ipa one each, GLOW, Mito and Flow State three each, KLOW six). None of the 18 is among the 38 tested pairs, so no stack can count, and every row reads "none published".
- **Why it can't drift:** the build already stops (`receipt_html`) if a named stack ever holds a tested or noted pair, until its receipt has a row for it. The number agrees with that guard.
- **The second check:** `hero_meter.py` works the number out again from the raw data, in its own code, and holds the page's number, italic line, scope, hero order and every row's phrase to it.
- **Proof the check bites:** each planted fault was caught (a wrong number, "have" for 0, a wrong scope count, a row's phrase, the H1 moved, the block removed). A test copy of the data that marked Wolverine's pair as tested moved the expected number to 1 and the rows to "1 of 3 pairs" (GLOW), "1 of 6 pairs" (KLOW) and "1 of 1 pair" (Wolverine).

## DECISIONS

- **D1. The drawing in the page, for every visit.** It sits above the fields on a first visit, a remembered one and a linked one. The syringe choices and the pen's note stay in their panels and still wait for the three, as fix 4 had them.
- **D2. The scale is drawn into the page** as the script draws it at 390 px, so the first paint has it before the script runs. The script redraws it for the width it finds.
- **D3. The line under the drawing hides without collapsing** (`visibility`), so the fields never move. Without JavaScript it isn't shown at all, since nothing would fill.
- **D4. The /stacks/ figures come from the data, not from the words.** The number, each row's phrase and the scope's counts are computed. The goals are fixed words, and the build holds them to each stack page's eyebrow.
- **D5. Page content versus generated.** The door row is page content, as the old button was. The pairs' label is generated with its count.
- **D6. `.vercelignore` names each file,** as the file always has. A `data/` pattern would also catch a future file a page fetches.
- **D7. The sweep's three new checks:**
  - the network log;
  - 404s, which fail the sweep;
  - dead links, also failing: same-site targets checked after vercel.json's redirects, which the sweep reads itself.
  - The proof's script and inputs are in `gsc-export/fix-5-2026-10-15/sweep/`.
- **D8. Checklist and cache.** `scripts/gen_sitemap.py` is on the checklist, after the last prerender. The calculator's worker cache is now `kalios-calc-v7`.
